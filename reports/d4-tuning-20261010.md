# 一次データ走査の再計測と最適化

2026-10-10。Crystal 1.21.1 の `--release` ビルドを使用。`bench/compare.cr` で生成した同一ファイルを改善前後のバイナリで読み、`hyperfine --warmup 2 --runs 9` でプロセス全体の実行時間を測った。ローカルファイルのページキャッシュが温まった状態での小規模な計測である。

| 処理 | 改善前 | 改善後 | 変化 |
|---|---:|---:|---:|
| 一次データ 64M 塩基の走査 | 140.4 ± 2.2 ms | 117.7 ± 0.8 ms | 16.2% 短縮 |
| 二次データを含む 5M 塩基の走査 | 14.1 ± 0.5 ms | 12.8 ± 0.4 ms | 9.2% 短縮 |
| 一次データ 4,096 点の参照 | 19.4 ± 0.3 ms | 19.8 ± 0.6 ms | 明確な改善なし |

平均 ± 標準偏差を記載した。一次走査のチェックサムは両版とも 224,000,000、二次データを含む走査は両版とも 22,400,000。`GC.stats.total_bytes` の差分は各走査で両版同一だった。

単純範囲辞書の一次デコードで、辞書種別と範囲の判定を塩基ごとのループから外した。辞書の要素数は 2 のべき乗であり、bit width に収まるコードはすべて辞書の範囲内となる。値リスト辞書は従来のデコード経路を使う。負の下限を持つ範囲辞書も既存の幅別相互運用テストに追加した。

点参照のため `LocalSource` を `File#read_at` に替える試みも測定したが、4,096 点で約 45 ms と遅くなったため採用しなかった。最終変更にこの試みは含まれない。

非 HTTP の Crystal spec は 32 件成功し、`crystal tool format --check src spec` も成功した。HTTP の 3 件は実行環境で loopback socket の作成が許可されず、今回の通過件数に含めていない。
